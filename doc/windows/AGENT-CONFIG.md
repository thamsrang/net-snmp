# Configuring the Net-SNMP agent (`snmpd`) on Windows

This guide covers `snmpd.conf` for the agent built in this tree. Every example below was run against a temporary agent (UDP ports 1167-1171 on `127.0.0.1`) and the shown results are real, unless a note says it was not tested. Use port 161 on a real machine.

Related: [BUILD.md](BUILD.md), [INSTALLERS.md](INSTALLERS.md), [CLIENT.md](CLIENT.md), [SERVICE.md](SERVICE.md) and [REQUEST-CAPTURE.md](REQUEST-CAPTURE.md).

## 1. Where the configuration lives

After installing, the agent reads `snmpd.conf` from `C:\Program Files\Net-SNMP\etc\snmp` (the folder in `SNMPCONFPATH`). Edit it from an elevated editor.

Useful command-line options:

| Option | Meaning |
|--------|---------|
| `-c <file>` | also read this config file |
| `-C` | do not read the default config files (use with `-c` for a clean test) |
| `-f` | stay in the foreground |
| `-Lo` / `-Lf <file>` | log to the console / to a file |
| `-H` | print every config directive the agent understands, then exit |

`snmpd -H` lists 169 lines of directives for this build (for example `rocommunity`, `rouser`, `agentaddress`, `trap2sink`, `extend`). It is the authoritative list.

The Perl wizard `snmpconf` is not part of this build, so write the file by hand.

### Do not let the agent overwrite your config

`snmpd` stores its own state (engine boot count, SNMPv3 users it created) in a file named `snmpd.conf` in its **persistent folder**. If the persistent folder is the same as the config folder, the agent replaces your file with its "DO NOT EDIT THIS FILE" data and then ignores your settings. This happened during testing.

Keep them apart. Without an override the persistent folder is `/var/net-snmp`, which resolves to `\var\net-snmp` on the current drive. To choose a proper folder:

```
mkdir C:\ProgramData\Net-SNMP\persist
setx /M SNMP_PERSISTENT_DIR "C:\ProgramData\Net-SNMP\persist"
```

Open a new terminal (and restart any service) afterwards.

## 2. Applying changes

The agent reads its config at start. Restart it after editing: stop and start the service (`sc.exe stop "Net-SNMP Agent"`, `sc.exe start "Net-SNMP Agent"`), or stop and rerun a foreground `snmpd`. Online reload was not tested.

## 3. A working starting point

This combined file was tested end to end (v2c read, v3 read, write refused, `extend` output; the agent log showed no errors). Replace the communities, passphrases and addresses. For production use `agentaddress udp:161`.

```
agentaddress udp:127.0.0.1:1170
sysLocation Server room 1
sysContact admin@example.com
rocommunity monitor 127.0.0.1
createUser monitorV3 SHA-256 authpass123 AES privpass123
rouser monitorV3 priv
trap2sink 127.0.0.1:1171 monitor
authtrapenable 1
extend uptime-check cmd /c echo ok
```

Results:

```
snmpget -v2c -c monitor ... sysLocation.0 sysContact.0
  SNMPv2-MIB::sysLocation.0 = STRING: Server room 1
  SNMPv2-MIB::sysContact.0 = STRING: admin@example.com

snmpget -v3 -l authPriv -u monitorV3 -a SHA-256 -A authpass123 -x AES -X privpass123 ... sysLocation.0
  SNMPv2-MIB::sysLocation.0 = STRING: Server room 1

snmpset -v2c -c monitor ... sysLocation.0 s X
  Error in packet.  Reason: noAccess

snmpwalk -v2c -c monitor ... NET-SNMP-EXTEND-MIB::nsExtendOutput1Line
  NET-SNMP-EXTEND-MIB::nsExtendOutput1Line."uptime-check" = STRING: ok
```

Each part is explained next.

## 4. Where the agent listens: `agentaddress`

```
agentaddress udp:161
agentaddress udp:127.0.0.1:1170,udp6:[::1]:1170
```

- `udp:161` listens on all IPv4 addresses on port 161.
- Several listeners can be given with commas, including IPv6. Both `udp:127.0.0.1:1170` and `udp6:[::1]:1170` answered in the test.
- Port 161 may need a firewall rule for remote managers (`netsh advfirewall firewall add rule ... localport=161`).
- If another SNMP agent (such as the built-in Windows "SNMP Service") already holds UDP 161, `snmpd` cannot use it.

## 5. Simple access control: communities (SNMPv1 and v2c)

```
rocommunity public  192.168.1.0/24
rwcommunity private 192.168.1.10
rocommunity6 public ::1
```

Syntax: `rocommunity <community> [<source> [<oid>]]`. `rwcommunity` allows writes. IPv6 sources use `rocommunity6` and `rwcommunity6`.

Restricting by OID (tested):

```
rocommunity public 127.0.0.1 .1.3.6.1.2.1.1
```

```
snmpget ... sysName.0            -> value returned
snmpget ... ifDescr.1            -> No Such Object available on this agent at this OID
snmpwalk ... ifDescr             -> No more variables left in this MIB View
```

Restricting by source address (tested):

```
rocommunity public 10.9.9.9
```

A query from `127.0.0.1` with that community gets **no reply at all** (client: `Timeout: No Response`). Wrong source and wrong community look identical to the client, so check the agent log (`snmpd -V`) when debugging.

Rules of thumb:

- Never leave the example names `public` and `private` on a real machine.
- Give each community the narrowest source and OID that works.
- Use a different, hard-to-guess community for write access, or do not allow writes at all.
- Community strings travel in clear text; use SNMPv3 across untrusted networks.

## 6. SNMPv3 users

```
createUser monitorV3 SHA-256 authpass123 AES privpass123
rouser monitorV3 priv
```

- `createUser <name> <auth-protocol> <auth-pass> [<priv-protocol> <priv-pass>]`. Passphrases need at least 8 characters.
- Authentication protocols tested: `MD5`, `SHA`, `SHA-256`. The tool's help also lists `SHA-224`, `SHA-384`, `SHA-512` (not tested).
- Privacy protocols available: `DES` and `AES` (AES-128). AES-192 and AES-256 are **not** available in this build; `createUser ... AES-256` fails with `unknown privProtocol`.
- `rouser <name> [noauth|auth|priv]` or `rwuser`: the **minimum** security level required. With `priv`, a request using only authentication is refused: the test gave `authorizationError (access denied to that object)`.
- On first start the agent turns the `createUser` line into stored keys in its persistent folder. After that, delete the `createUser` line so the passphrases do not stay in a plain-text file.
- Query examples and how to confirm from the log which algorithms were used: section 3 of [CLIENT.md](CLIENT.md) and sections 5 and 6 of [REQUEST-CAPTURE.md](REQUEST-CAPTURE.md).

## 7. Full access control (VACM)

For several groups of managers with different rights, use the four VACM directives instead of `rocommunity`. Tested:

```
com2sec readonly 127.0.0.1 public
com2sec admin    127.0.0.1 private
group MyRO v2c readonly
group MyRW v2c admin
view sysview included .1.3.6.1.2.1.1
view all     included .1
access MyRO "" any noauth exact sysview none none
access MyRW "" any noauth exact all     all  none
```

How it fits together: `com2sec` maps a community and source to a security name; `group` puts that name in a group; `view` defines a set of OIDs; `access` gives a group a read view, a write view and a notify view.

Results from the test:

| Request | Outcome |
|---------|---------|
| `public`, read `sysName.0` | value returned |
| `public`, read `ifDescr.1` | `No Such Object` (outside `sysview`) |
| `public`, write `sysLocation.0` | `Error in packet. Reason: noAccess` |
| `private`, write `sysLocation.0` | succeeded, and reading it back returned the new value |

## 8. System information: `sysLocation`, `sysContact`, `sysName`

```
sysLocation Server room 1
sysContact admin@example.com
```

- If you set them in `snmpd.conf`, they become **read-only** over SNMP. Tested: with `sysLocation Fixed` in the file, a write from an `rwcommunity` returned `notWritable`.
- If you leave them out, a manager with write access can change `sysLocation.0` (tested: the write succeeded and the new value was read back). Whether such a value survives an agent restart was not tested.
- `sysContact` shows `@@no.where` until you set it. `sysName` defaults to the computer name.

## 9. Running a command and publishing its output: `extend`

```
extend uptime-check cmd /c echo ok
```

```
snmpwalk ... NET-SNMP-EXTEND-MIB::nsExtendOutput1Line
  NET-SNMP-EXTEND-MIB::nsExtendOutput1Line."uptime-check" = STRING: ok
```

The output, number of lines, full text and exit code appear under `NET-SNMP-EXTEND-MIB` (`nsExtendOutput1Table`, `nsExtendResult`). Use `cmd /c ...` for shell built-ins.

Security: the command runs as the account of the agent (LocalSystem when running as a service). Only commands written in `snmpd.conf` can be run, but anyone allowed to read that part of the MIB can trigger them and see the output. Keep commands fixed, harmless and fast, and keep the file writable only by administrators.

`exec`, `pass`, `pass_persist`, `proxy`, `disk` and `load` were not tested.

## 10. Sending traps from the agent

```
trap2sink 127.0.0.1:1171 monitor
authtrapenable 1
```

- `trap2sink <host>[:port] <community>` sends SNMPv2c traps. `trapsink` sends v1 traps and `informsink` sends informs (not tested).
- `authtrapenable 1` sends an `authenticationFailure` trap when a request arrives with a wrong community.

With a `snmptrapd` listening (see section 2 of [REQUEST-CAPTURE.md](REQUEST-CAPTURE.md)), the test showed two traps:

```
SNMPv2-MIB::snmpTrapOID.0 = OID: SNMPv2-MIB::coldStart                 (sent when the agent started)
SNMPv2-MIB::snmpTrapOID.0 = OID: SNMPv2-MIB::authenticationFailure     (sent after a query with a wrong community)
```

## 12. Hardening checklist

- No default community names; restrict each community by source and OID.
- Prefer SNMPv3 with `authPriv`, SHA-256 and AES-128 (the strongest available here).
- Do not expose UDP 161 to untrusted networks; scope the firewall rule to your management subnet.
- Separate read and write access; avoid `rwcommunity` unless you need it.
- Remove `createUser` lines after the first start.
- Keep config and persistent folders separate, and writable only by administrators.
- Log requests while testing (`-V`) and turn it off when done.

## 13. Troubleshooting

| Symptom | Likely cause |
|---------|--------------|
| `Warning: no access control information configured` at start | the config file was not read (wrong `SNMPCONFPATH`, no rules in it, or the agent overwrote it; see section 1) |
| Client times out | wrong IP or port, firewall, wrong community, source not allowed, or the agent is not running |
| `Unknown user name` | the v3 user was not created (check the config file, and the log for `unknown privProtocol`) |
| `noAccess` | the community or user has no write view (sections 5 and 7) |
| `notWritable` | the object is read-only, for example `sysLocation` set in `snmpd.conf` |
| Config line error at startup, such as `unknown privProtocol` | an unsupported value (AES-256 here) |
| `snmpd` exits immediately | run `snmpd.exe -f -Lo` in a console to read the message |
