# Running the agent (`snmpd`) as a Windows service and at startup

Part of the [Windows documentation](README.md). Related: [agent configuration](AGENT-CONFIG.md), [installers](INSTALLERS.md), [request logging](REQUEST-CAPTURE.md) and [client tools](CLIENT.md).

The steps below come from reading `snmplib/winservice.c` and `agent/snmpd.c`. They were not run, because registering a service needs an elevated prompt.

This guide is about the agent side, which a client talks to. It is not needed for client-only use.

`snmpd.exe` and `snmptrapd.exe` have built-in Windows service support. The installers register `snmpd` only if you ask them to (NSIS: the service component or `/SERVICE=1`; MSI: `REGISTER_SERVICE=1`; see [INSTALLERS.md](INSTALLERS.md)). Otherwise, or for `snmptrapd`, do it once yourself as described below.

| Program | Service name (use in `sc`/`net`) | Display name |
|---------|----------------------------------|--------------|
| `snmpd.exe` | `Net-SNMP Agent` | Net-SNMP Agent |
| `snmptrapd.exe` | `Net-SNMP Trap Handler` | Net-SNMP Trap Handler |

The names contain spaces, so always quote them. In PowerShell write `sc.exe`, not `sc`: `sc` is an alias for `Set-Content` there and will not manage services.

## 1. Before registering

1. Install with the NSIS setup or the MSI, then open a **new** elevated terminal (Run as administrator). Registering needs administrator rights.
2. Create the agent config `C:\Program Files\Net-SNMP\etc\snmp\snmpd.conf` (the folder exists after install; `SNMPCONFPATH` points there). Minimal read-only example:
   ```
   agentaddress udp:161
   rocommunity public 192.168.1.0/24
   sysLocation Server room 1
   sysContact admin@example.com
   ```
   Replace the community and network. With no config file, `snmpd` starts but answers nobody.
3. Optional but recommended for SNMPv3 users created on the agent: the built-in default location for persistent data is `/var/net-snmp`, which on Windows is `\var\net-snmp` on the current drive. Set a real folder instead, and create it:
   ```
   mkdir "C:\ProgramData\Net-SNMP\persist"
   setx /M SNMP_PERSISTENT_DIR "C:\ProgramData\Net-SNMP\persist"
   ```
   Do **not** point it at the config folder. `snmpd` writes its own state to a file named `snmpd.conf` in the persistent folder and overwrites any file of that name, which destroys your configuration. This was reproduced while testing: after one start the config file had been replaced by the "DO NOT EDIT THIS FILE" persistent-data file, and the agent then ignored its settings.
4. Test in the foreground first. Fix any errors before making it a service:
   ```
   snmpd.exe -f -Lo
   ```
   Stop it with Ctrl+C. From another terminal, `snmpget -v2c -c public 127.0.0.1 sysDescr.0` should answer.
5. Allow UDP 161 in the firewall if remote clients will query it:
   ```
   netsh advfirewall firewall add rule name="Net-SNMP snmpd UDP 161" dir=in action=allow protocol=UDP localport=161 program="C:\Program Files\Net-SNMP\sbin\snmpd.exe"
   ```

## 2. Register as a service

From an elevated prompt:

```
snmpd.exe -register
```

What this does (from `snmplib/winservice.c` and `agent/snmpd.c`):

- Creates the service `Net-SNMP Agent` with start type **Automatic**, so it starts at boot.
- The service command is `"<full path of snmpd.exe>" -service`. The path is the one you ran `-register` from, so run it from the installed `C:\Program Files\Net-SNMP\sbin`, not from a build folder or a temporary copy.
- No account is set, so it runs as **LocalSystem**.
- Adds an Application event-log source for the service.

Any options after `-register` are saved and used every time the service starts. They are stored one per value in `HKLM\SYSTEM\CurrentControlSet\Services\Net-SNMP Agent\Parameters` (`Param1`, `Param2`, ...). Add `-quiet` right after `-register` to suppress the message boxes. Example with a log file (a service has no console, so log to a file):

```
snmpd.exe -register -quiet -Lf C:\ProgramData\Net-SNMP\snmpd.log -p C:\ProgramData\Net-SNMP\snmpd.pid
```

Create the folder first. To change the saved options later, unregister and register again, or edit the `Param` values in the registry.

Register the trap receiver the same way if you need it:

```
snmptrapd.exe -register
```

`snmptrapd` needs an `snmptrapd.conf` in the same config folder (for example `authCommunity log,execute,net public`), otherwise received traps are dropped.

## 3. Start, stop, check

```
sc.exe start "Net-SNMP Agent"
sc.exe query "Net-SNMP Agent"
sc.exe stop "Net-SNMP Agent"

net start "Net-SNMP Agent"
net stop "Net-SNMP Agent"
```

Or use `services.msc` and look for **Net-SNMP Agent**. Then test from a client:

```
snmpget -v2c -c public 127.0.0.1 sysDescr.0
```

If the service does not start:

- **Environment variables.** The service gets `MIBDIRS` and `SNMPCONFPATH` from the system environment. If you installed and then started the service without rebooting, it may not see them. Reboot once after installing.
- **Event Viewer.** Windows Logs, Application, source `Net-SNMP Agent`.
- **Log file.** If you registered with `-Lf`, read that file.
- **Port in use.** Another SNMP service (the built-in Windows "SNMP Service") may already own UDP 161. Stop and disable it, or use another port with `agentaddress udp:1161`.
- **Config errors.** Run `snmpd.exe -f -Lo` in the foreground to see them.

The source marks the service stop path as incomplete (`StopSnmpAgent`: "This portion is still not working"), so `stop` can be slow or fail to end the process cleanly. If it hangs, end `snmpd.exe` in Task Manager or with `taskkill /f /im snmpd.exe`.

## 4. Run on startup

The registered service is already **Automatic**, so it starts at boot with no further steps. Options to adjust this:

```
rem Start a little after boot, when the network is up
sc.exe config "Net-SNMP Agent" start= delayed-auto

rem Start manually only
sc.exe config "Net-SNMP Agent" start= demand

rem Disable
sc.exe config "Net-SNMP Agent" start= disabled

rem Restart automatically if it crashes (after 5 s, 5 s, 30 s; reset counter daily)
sc.exe failure "Net-SNMP Agent" reset= 86400 actions= restart/5000/restart/5000/restart/30000
```

The space after `start=` is required.

**If you do not want a service.** Use a Task Scheduler task that runs at startup in the foreground. From an elevated prompt:

```
schtasks /Create /TN "Net-SNMP snmpd" /SC ONSTART /RU SYSTEM /RL HIGHEST /TR "\"C:\Program Files\Net-SNMP\sbin\snmpd.exe\" -f -Lf C:\ProgramData\Net-SNMP\snmpd.log"
schtasks /Run /TN "Net-SNMP snmpd"
schtasks /End /TN "Net-SNMP snmpd"
schtasks /Delete /TN "Net-SNMP snmpd" /F
```

This avoids the service-stop issue above but gives no service-style status or recovery options. For a logged-in user only, a shortcut to `snmpd.exe -f` in `shell:startup` also works, but it stops at logoff.

## 5. Remove the service

```
snmpd.exe -unregister
snmptrapd.exe -unregister
```

The service is stopped first if it is running, then deleted, and its event-log registry key is removed. The current NSIS uninstaller and MSI run `-unregister` for both services on uninstall, so you normally do not need to do this yourself. Do it by hand when you remove Net-SNMP some other way (for example by deleting the folder); if an entry is left behind pointing at a deleted file, delete it with `sc.exe delete "Net-SNMP Agent"`.

## 6. Checklist

| Step | Command |
|------|---------|
| Config in place | `C:\Program Files\Net-SNMP\etc\snmp\snmpd.conf` |
| Foreground test | `snmpd.exe -f -Lo` |
| Firewall | `netsh advfirewall firewall add rule ...` (section 1) |
| Register (elevated) | `snmpd.exe -register -quiet -Lf <logfile>` |
| Start | `sc.exe start "Net-SNMP Agent"` |
| Auto-start at boot | already set; optionally `start= delayed-auto` |
| Verify | `snmpget -v2c -c public 127.0.0.1 sysDescr.0` |
| Remove | `snmpd.exe -unregister` |
